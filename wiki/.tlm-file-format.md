Some of the fields are packed with the var-length encoder. See implementation details here:

* [var-int](https://github.com/ugcs/ugcs-java-sdk/blob/master/ucs-common/src/main/java/com/ugcs/common/util/codec/BytesCodec.java#L186)
* [var-long](https://github.com/ugcs/ugcs-java-sdk/blob/master/ucs-common/src/main/java/com/ugcs/common/util/codec/BytesCodec.java#L231)
* [var-string](https://github.com/ugcs/ugcs-java-sdk/blob/master/ucs-common/src/main/java/com/ugcs/common/util/codec/BytesCodec.java#L413)
* [var-bytes](https://github.com/ugcs/ugcs-java-sdk/blob/master/ucs-common/src/main/java/com/ugcs/common/util/codec/BytesCodec.java#L139)

And there some markers used in there.

`SIGNATURE = D8 EE BC BE (-655442754)`

`VERSION = 00 00 00 01 (1)`

`NULL = 01 (encoded as var-int)`

`END_OF_TELEMETRY = 80 80 80 80 08 (0x80000000 encoded as var-int)`

## Header

First 8 bytes of the telemetry file contain format signature and version. Succeeding payload is version-specific.

```
4 bytes: SIGNATURE
4 bytes: VERSION
var-length: PAYLOAD
EOF
```



## Payload (v.1)

Payload contains attributes and telemetry of multiple vehicles.

```
var-length: vehicle 1 attributes
1 byte: NULL
var-length: vehicle 1 telemetry
5 bytes: END_OF_TELEMETRY
...
var-length: vehicle n attributes
1 byte: NULL
var-length: vehicle n telemetry
5 bytes: END_OF_TELEMETRY
```

## Vehicle attributes (v.1)

Attributes section is of variable length and consists of string key-value pairs. Null key stands for the end of the attributes section.

```
var-string: key 1
var-string: value 1
var-string: key 2
var-string: value 2
...
var-string: key n
var-string: value n
1 byte: NULL
```

Here is the list of the possible attribute keys.

| Key | Required | Value |
| --- | ---- | ---- |
| range.from | false | Beginning of the exported interval. Telemetry time should not be before this value. Millis from Epoch. |
| range.to | false | End of the exported interval. Telemetry time should not be after this value. Millis from Epoch. |
| vehicle.vehicleType | false | Vehicle type name, one of the following: FIXED_WING, HELICOPTER, MULTICOPTER. |
| vehicle.platform.code | false | Platform code. See Platform.code db field for the list of the available platforms. |
| vehicle.serialNumber | false | Vehicle serial number, reported by the VSM. |
| vehicle.port | false | Vehicle port, reported by the VSM. |
| vehicle.name | false | Vehicle name. |
| vehicle.tailNumber | false | Vehicle tail number. |

## Vehicle telemetry (v.1)

Telemetry section is a list of rows either of telemetry value or field declaration. Every row starts with the numeric field index. First mention of the index within the section stands for the field declaration row. Every further mention of the index stands for the value row.

```
var-length: field 1 declaration row
var-length: field 1 value
var-length: field 1 value
...
var-length: field 2 declaration row
var-length: field 1 or 2 value
var-length: field 1 or 2 value
var-length: field 1 or 2 value
...
var-length: field n declaration row
var-length: field 1 or 2 ... n value
var-length: field 1 or 2 ... n value
...
var-length: END_OF_TELEMETRY
```

Field declaration row:

```
var-int: field index (first mention of the value)
var-string: field code (as reported by VSM)
var-string: field semantic name
var-string: subsystem (CONTROL_SYSTEM(0), FLIGHT_CONTROLLER(1), GIMBAL(2), CAMERA(3), ADSB_TRANSPONDER(4))
var-int: subsystem id (a subsystem sequence number)
```

Telemetry value row:

```
var-int: field index (listed above)
var-long: telemetry time (millis from Epoch)
var-bytes: telemetry value (binary encoded)
```
